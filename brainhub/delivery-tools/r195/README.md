# R2544.195 — entry evidence and operational failure provenance

When entry history contained array-shaped prose summaries, the 48,000-byte
request ceiling could prevent the JEV request entirely. In the combined lane,
the operational failure then followed the provider-outage continuation policy,
and the UI and later desk advice presented its synthetic REJECT_ENTRY as if it
were a strategic model answer.

This candidate:

- Removes duplicated archived learning prose only when its measured factor
  table exists. Current numerical market evidence, the proposed entry plan,
  measured aggregates and winner/loser counterexamples stay intact. No learning
  database or preferences are rewritten. The request ceiling is unchanged.
- Projects prior request-size diagnostics and local trace details out of
  archived entry features. Prior decision/availability and delivery status
  remain; the complete transport diagnostics stay in local journals. This
  prevents each newly closed entry from inflating the next decision request.
- Treats local context size/truth failures as entry integrity failures in İlk 3
  v2 and ZİRVE-5. Those failures cannot open an entry through the provider-outage
  policy. Genuine JEV approval/rejection and the existing credit/timeout policy
  remain distinct; no strategy score or market filter is added.
- Preserves ok/called/status/rawDecision separately in new lot records, the
  Office projection and desk advice. An operational failure has no strategic
  decision. Bare legacy decisions remain unverified; original entry evidence
  can restore the status. Historical journals are not rewritten.
- Corrects Office explanations of sizing, entry authority and selected sub-lanes.
- Extends read-only diagnostics with desk/close events and the traces referenced
  by real entries, even after newer scans push them out of the latest-30 list.

The PC runtime/Office/mobile status release advances together to R2544.195.
No Android binary or phone installation is part of this candidate.

Validation and immutable candidate identity belong in the delivered manifest.
Windows acceptance must run natively on the same commit before staging/deploy.
Linux tests, captured-request replays and synthetic regression checks do not
establish live profitability, predict the model's counterfactual decision, or
prove that every future request will fit. Irreducible packets still fail
explicitly. Installed state and a currently open position must not be changed
as part of isolated acceptance.
