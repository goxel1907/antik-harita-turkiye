# R2544.18 Free Provider Resilience Research

Date: 2026-09-30

## Scope

This release does not change JEV final authority, Binance execution, mandatory safety, position sizing, stops, or the discovery-first priority ladder. The changes are limited to optional evidence/research workers, provider health telemetry, and Headroom integration safety.

## Headroom 401 root cause

BrainHub itself listens on `127.0.0.1:8787`. 9Router's documented Headroom default also points to `http://localhost:8787` and calls `/v1/compress`. Therefore a default Headroom configuration on this PC reaches BrainHub, not Headroom, and BrainHub correctly returns an authorization/error response. This is a local port collision, not a model-inference failure.

R2544.18 reserves `127.0.0.1:8788` for the optional Headroom sidecar. `HEADROOM-SETUP.ps1` refuses 8787, can install the official `headroom-ai[proxy]` package, starts it loopback-only on 8788, and Office probes `/health` separately. 9Router must be pointed once to `http://127.0.0.1:8788`. If Headroom is not wanted, disable it in 9Router and keep its built-in RTK token saver; helper compression must never block JEV.

## OpenRouter free evidence pool

Primary helper route remains `openrouter/free`, because OpenRouter dynamically chooses among currently available free models. R2544.18 also keeps a small explicit **free-only** fallback pool so an upstream failure in the dynamic route does not immediately remove the optional second opinion:

- `inclusionai/ling-3.0-flash-fin:free` — finance-oriented evidence/reasoning fallback.
- `nvidia/nemotron-3-ultra-550b-a55b:free` — long-context reasoning/orchestration fallback.
- `nvidia/nemotron-3-super-120b-a12b:free` — reasoning fallback.
- `google/gemma-4-26b-a4b-it:free` — multimodal/general reasoning fallback.
- `inclusionai/ling-3.0-flash-vl:free` — multimodal evidence fallback.

The worker rejects any model that is neither `openrouter/free` nor an ID ending in `:free`. A 429 does not spray the same key across multiple endpoints. Helper output remains advisory (`optional=true`, `blocksJev=false`).

## 9Router OpenCode Free discovery

The current static OpenCode list is retained as a bootstrap baseline. R2544.18 also queries the local 9Router OpenAI-compatible `/v1/models` endpoint and dynamically adds newly exposed `oc/*` routes. Only the OpenCode prefix is accepted for automatic text-helper discovery. Kiro routes remain quota/account-dependent and are not promoted into the automatic text pool.

This avoids hard-coding the entire 9Router free catalog while keeping the authority boundary clear: these models can collect or review evidence, but cannot approve an order.

## Health semantics

Per-model telemetry now distinguishes:

- `healthy`
- `cooldown`
- `failed`
- `untested`

Failures are additionally classified as `AUTH`, `RATE_LIMIT`, `OVERLOADED`, `UPSTREAM_UNAVAILABLE`, `TIMEOUT`, `CONNECTION`, or generic `FAILED`. Office groups 9Router OpenCode Free, 9Router Kiro quota, local Vision, and OpenRouter free pool separately and shows attempts/successes/failures/latency/reason.

A model that was actually tried is no longer described as `untested` merely because its cooldown expired. Kiro Vision attempts are surfaced even when no text-comittee attempt exists.

## Design rule

Free providers are volatile. The system must fail open around optional evidence, not around execution safety. `typesafe/jev-1.13` remains the JEV decision owner. No free model can place an order, create a mandatory veto, or bypass the post-JEV mechanical safety layer.
