# R2544.27 — Binance Rate-Limit Hardening

R2544.27 is a transport-safety hotfix on top of R2544.26. JEV strategy/decision authority, risk, stop/TP, scanner ranking semantics, case-memory authority and 42k/46k/48k context-budget limits are unchanged.

## What changed
- One process-wide Binance REST guard is shared by scanner, public market context and signed LIVE transport.
- Default concurrency is capped at 4 and request starts are paced by 25 ms.
- A conservative local 60-second request-weight estimate protects headroom: public evidence soft guard 1600, signed LIVE reads 1900. LIVE writes are not blocked by the soft estimate, but they still obey exchange 429/418 cooldowns.
- `X-MBX-USED-WEIGHT-1M` is observed when Binance returns it, so traffic from other activity on the same public IP can trigger local public/read protection.
- HTTP 429 honors `Retry-After` (fallback 60 s). HTTP 418 honors the ban-until timestamp/`Retry-After` (fallback 5 min). During cooldown, requests fail locally instead of continuing to hit Binance.
- USD-M WebSocket connections use the supported `wss://fstream.binance.com/ws` path for subscription-mode streams.
- Health/Office expose the guard state.

## Authority
Rate-limit protection is transport safety only. It cannot produce LONG/SHORT/WAIT, cannot qualify a setup and does not alter JEV evidence weights. Optional market evidence may become unavailable during protection; missing optional evidence is not negative evidence. LIVE remains fail-closed when required exchange/account data cannot be read.

## Context budget
PASS-1 target 42,000 B; PASS-2 target 46,000 B; hard max 48,000 B. Unchanged from R2544.26.
