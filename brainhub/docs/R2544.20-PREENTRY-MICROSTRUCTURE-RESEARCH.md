# R2544.20 Pre-Entry Microstructure / Adverse-Selection Research

Build date: 2026-09-30
Release target: `R2544.20-PREENTRY-MICROSTRUCTURE`

## 1. Problem being solved

JEV remains the only strategic decision authority, but a structurally valid 5m or 15m thesis can still be entered at a poor instant. The failure mode is not necessarily the higher-timeframe direction; it can be adverse selection immediately around entry: aggressive market buying that cannot lift price, aggressive selling that cannot push price lower, displayed liquidity disappearing on the side that would protect the entry, opposite-side replenishment, worsening spread, or a queue/microprice shift against the intended trade.

R2544.20 therefore adds a deterministic **pre-entry adverse-selection evidence layer**. It does not predict a named market maker, Binance bot, hidden order, or participant intent. Public Binance feeds do not expose enough information to prove those identities or intentions. The layer describes observable behavior only and gives JEV additional evidence for `MARKET_NOW` versus a timing wait.

The layer is deliberately not an execution gate. `canQualify=false`, `canVeto=false`, `canSize=false`, `canExecute=false`, `executionAuthority=false`. JEV remains final. Low-reliability/warming microstructure cannot veto an otherwise sound plan.

## 2. Public market-data inputs used

BrainHub already consumes Binance USD-M public WebSocket/REST market data. R2544.20 reuses those feeds; no private exchange endpoint or trading secret is added.

### `bookTicker`

Best bid/ask price and size observations are retained for up to roughly 130 seconds. Consecutive observations are used for a Level-1 Order Flow Imbalance (OFI) calculation based on the Cont-Kukanov-Stoikov event contribution. This is a sequenced best-quote OFI signal; it is **not** a full Level-2 or Level-3 reconstruction.

For each 5s/15s/30s/60s/120s window the runtime can expose:

- normalized Level-1 OFI in `[-1,1]`
- number of observed transitions
- window coverage
- mid-price move in basis points
- current/mean/delta top-queue imbalance
- best-quote microprice lead in basis points

The normalized value is `sum(OFI contribution) / sum(abs(OFI contribution))`; this is an index, not expected return or probability.

### `aggTrade`

Signed public taker flow (Binance maker flag) is measured over 5s/10s/15s/30s/60s/120s windows. The packet records buy/sell notional, imbalance, trade count, price response, large prints and an explicitly labelled TWAP-like regularity heuristic.

### partial `depth20@100ms`

The runtime retains partial-book snapshots and derives displayed-depth pressure, spread baseline/expansion, persistent walls, possible liquidity pulls, replenishment and absorption. This stream is **not** claimed to be true multi-level OFI. All labels are public-data heuristics.

### public derivatives / force-order context

Open interest delta, funding, taker ratio, top/global long-short ratios and observed force-order/liquidation prints remain contextual evidence. Observed liquidations are not a future liquidation heatmap.

## 3. Pre-entry evidence model

`brainhub/preentry-microstructure.js` calculates separate LONG and SHORT evidence. Every component has a signed value and a weight. Positive values support immediate execution in that side; negative values add adverse-selection/trap evidence for that side.

Current component families:

1. `FLOW_RESPONSE_5s/15s/30s/60s`
   - compares signed taker aggression with actual trade-price response.
   - same-side aggression without same-side price progress is adverse evidence.

2. `L1_OFI_RESPONSE_5s/15s/30s/60s`
   - compares sequenced Level-1 OFI with best-quote mid-price response.
   - same-side OFI without progress is adverse-selection evidence.

3. `FLOW_PERSISTENCE`
   - checks direction and consistency of taker-flow imbalance across multiple horizons.

4. `MICROPRICE_LEAD`
   - best-quote/depth microprice lead relative to mid.

5. `TOP_QUEUE_IMBALANCE` and `TOP_QUEUE_SHIFT`
   - best bid/ask queue imbalance and its 30-second change.

6. `DEPTH_IMBALANCE` and `PARTIAL_DEPTH_PRESSURE_ACCEL`
   - current partial-depth balance and its retained-snapshot change.

7. `ABSORPTION`
   - buyer aggression absorbed at displayed ask liquidity or seller aggression absorbed at displayed bid liquidity.

8. `LIQUIDITY_PULL_BIAS`
   - large displayed size disappearing without enough nearby traded notional to explain the removal.

9. `REPLENISHMENT_BIAS`
   - displayed side repeatedly remains/rebuilds while trades occur nearby.

10. `SPREAD_EXPANSION`
    - immediate execution-quality penalty when the spread expands materially above the retained baseline.

11. `CROWDING_WITH_OI`
    - modest contextual penalty when one-sided taker positioning coincides with rising OI. It is intentionally low-weight and cannot determine a trade alone.

The output includes:

- reliability index + quality (`HIGH/MEDIUM/LOW/INSUFFICIENT`)
- LONG continuation-support and trap-risk indices
- SHORT continuation-support and trap-risk indices
- strongest evidence components
- side-specific timing guidance (`FLOW_SUPPORTS_ENTRY`, `WAIT_FLOW_NORMALIZATION`, `FLOW_MIXED`, `DATA_INSUFFICIENT`)
- multi-window flow persistence
- compact Level-1 OFI windows
- a `toxicityProxy`, explicitly labelled `MEAN_ABS_TRADE_IMBALANCE_PLUS_L1_OFI_NOT_TRUE_VPIN`

No value is called a probability.

## 4. Reliability / fail-soft behavior

Reliability combines freshness, aggTrade coverage, partial-depth history, Level-1 OFI transition count, microprice availability, multi-window flow completeness, spread and cross-channel timestamp agreement. Sparse or warming data produces `DATA_INSUFFICIENT` rather than a synthetic zero.

This distinction matters: “no evidence” is not the same as “neutral evidence.” JEV is instructed not to let low-reliability pre-entry telemetry veto a sound 5m/15m setup.

## 5. JEV integration

The evidence enters the **core market packet** at:

`coreMarketPacket.microstructure.preEntryAdverseSelection`

It therefore survives optional learning/OSS-context trimming. The 52,000-byte whole-request cap remains unchanged. `CORE_MARKET_FIRST` still trims optional case-memory/knowledge/cortex prose before market truth. R2544.20 keeps the Level-1 OFI payload compact and does not include raw book histories in the JEV prompt.

PASS-2 receives a new diagnostic answer:

`pre_entry_flow_assessment`

Allowed values:

- `SUPPORTS_PLAN`
- `NEUTRAL_OR_MIXED`
- `TRAP_RISK_WAIT`
- `DATA_INSUFFICIENT`

`wait_reason` adds `ADVERSE_SELECTION_RISK`. A good direction/setup can therefore remain valid while JEV decides that `MARKET_NOW` is inferior and chooses `WAIT_NEW_EVIDENCE` for flow normalization. This remains a JEV judgment, not a deterministic gate.

## 6. Learning / case memory

R2544.19 immutable entry cases already freeze the decision-time 9TF market state and later attach the realized outcome. R2544.20 adds the pre-entry microstructure state to that frozen case and to case similarity.

The similarity vector can now compare:

- directional trap-risk index
- directional continuation-support index
- microstructure reliability
- toxicity proxy
- existing trend/structure/stretch/location/derivatives/flow fields

`trade-lessons.js` also records the selected side's pre-entry state. It creates *counterexample-safe* tags:

- `PREENTRY_TRAP_RISK`
- `LOSS_AFTER_PREENTRY_TRAP_RISK`
- `WIN_DESPITE_PREENTRY_TRAP_RISK`
- `PREENTRY_FLOW_SUPPORT`
- `WIN_WITH_PREENTRY_FLOW_SUPPORT`
- `LOSS_DESPITE_PREENTRY_FLOW_SUPPORT`

This is intentional. A trap-risk state that loses once is not declared bad forever, and a trap-risk state that wins once is not declared harmless. The digest adds `byPreEntryFlow` outcome groups so JEV can see both winners and losers under the same entry-time state. The evidence remains soft context and never becomes an automatic rule.

## 9. Why no live DeepLOB / bot-direction predictor was added

A neural LOB model without symbol-specific, time-aligned, leakage-safe training/validation data can create false confidence. Published/repository results also show a recurring constraint: the horizons with the strongest directional predictability can have moves smaller than fees/slippage, while larger moves can be less predictable.

R2544.20 therefore first builds high-quality deterministic telemetry, immutable entry cases and measured outcome calibration. Once enough R2544.20 cases exist, a future model can be trained **shadow-only** and judged on out-of-sample `+0.5R before -0.5R`, MFE/MAE, markout and fee-aware outcomes before it is ever allowed to influence JEV timing.

## 10. Safety / authority contract

Unchanged:

- JEV = final strategic decision maker.
- Scanner/radar = attention only.
- Optional models/research workers = evidence only.
- Pre-entry microstructure = evidence only.
- OSS = reference only.
- Case memory = soft measured experience only.
- self modification = off.
- automatic promotion of learned rules = off.
- execution authority = only existing protected live execution path after JEV and mandatory mechanical safety.

R2544.20 is intended to make JEV *better informed at the instant of entry*, not to replace JEV with another fixed rule or to claim certainty about hidden actors.
