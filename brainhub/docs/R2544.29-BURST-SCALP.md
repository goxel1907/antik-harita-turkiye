# R2544.29 — JEV BURST SCALP

## Purpose
R2544.29 adds a short-lived, JEV-preauthorized BURST_SCALP lane without changing the normal 5M_SCALP / 15M_TRADE authority model.

## Contract
- LONG and SHORT are symmetric. Scanner keeps the existing gainer ladder and adds a lightweight loser ladder for SHORT burst discovery.
- JEV may preauthorize at most four symbols (`ARM_LONG`, `ARM_SHORT`, `DO_NOT_ARM`) for 30/60/120 seconds. LONG/SHORT ranking context is symmetric: gainer rank/velocity and loser rank/velocity are both included. JEV cannot arm the opposite direction of the supplied preMove direction.
- Preauthorization is not an order. It specifies direction, TTL, trigger strictness, leverage policy and whether the one-per-pause strict exception is allowed.
- Armed symbols are watched every 1 second from public WebSocket evidence; detector windows include 1s/3s/5s aggTrade and 1s/3s L1 OFI plus sequence-safe local L2. No 1-second REST polling is introduced.
- A burst can execute only when the symbol is still JEV-armed, evidence is fresh, spread is acceptable, local L2 is healthy, 1s/3s flow and OFI agree, and deterministic ignition exceeds the JEV-selected threshold.
- BURST_SCALP has a separate slot (`burstSlots=1`) and does not consume the user's normal max-open-position slots.
- If any normal position is already open, burst margin is a separate configurable fraction of current Binance available balance (`burstFreeMarginFraction`, default 50%, allowed 10–50%). If flat, a separate `burstMarginQuote` is used (default: normal panel margin).
- Exchange leverage brackets are read at execution. `MAX_SAFE` starts from exchange maximum and is reduced by user burst cap (`burstMaxLeverage`, default 125), stop/liquidation safety and notional-bracket constraints; JEV may instead select `HALF_MAX` or `PANEL`.
- Same-symbol same-direction bursts are tracked as synthetic addons with exact-quantity burst stop/exit. The addon NEVER changes the symbol leverage of the already-open core position; it reuses the core leverage and fails closed if that leverage violates burst safety/user cap. Same-symbol opposite-direction burst is fail-closed in v1.
- Burst exits are fast: protective stop, ~0.45R fast fail, opposite flow reversal, MFE giveback, 0.8R fast-profit objective, or 120s time exit.
- Every burst is journaled separately (`BURST_ARM`, `BURST_ENTRY`, `BURST_CLOSED`, `BURST_BLOCKED`) and learning stores MFE/MAE, realized R, capture efficiency, trigger evidence and authority.
- The existing two-loss / 30-minute entry pause remains binding. During one pause, at most one JEV-preauthorized exception may execute, and only with `IGNITION` plus a >=0.94 strict trigger. The pause itself is not cancelled by that trade.

## Android
Android is read-only for BURST. `/live/burst` is GET-only in the app. The phone shows up to four armed symbols, active burst, and pause-exception state. Android never posts a burst order or `/live/execute`.

## Preserved safety
R2544.28 semantic consistency / executable management / REDUCE_RISK / learning hardening, R2544.27f Binance traffic hardening, PASS1 42k / PASS2 46k / wire 48k, PC-only order authority, and restart-LIVE-off behavior remain intact.
