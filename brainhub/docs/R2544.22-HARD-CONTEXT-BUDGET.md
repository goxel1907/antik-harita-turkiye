# R2544.22 — HARD CONTEXT BUDGET

## Problem observed live

R2544.21 fixed sparse-window microstructure confidence, but the live Office snapshot exposed a different bottleneck: a JEV request reached 57,413 bytes against the historical 52,000-byte whole-request ceiling, and a large fraction of recent analysis attempts were rejected before JEV could reason over them. PASS-1 and PASS-2 both use the same decision transport, so both phases can be affected.

The objective of R2544.22 is **not to give JEV less market truth**. The objective is to remove duplicate/redundant representations and build each request to an explicit phase-specific byte budget before it reaches the provider.

## Budget contract

- PASS-1 target: **42,000 bytes**
- PASS-2 target: **46,000 bytes**
- Other JEV requests target: **44,000 bytes**
- Whole-request hard ceiling: **48,000 bytes**
- Provider `max_tokens_exceeded` retry: one smaller **44,000-byte hard / 42,000-byte target** request

Targets are preferred operating envelopes. The hard ceiling remains fail-closed. A request is never allowed to silently exceed 48 kB.

## Quality-preservation order

The request builder now works in this order:

1. Remove pure duplicates such as `record.experienceMemory` when the canonical state memory already exists, and reduce `record.attention.baseFrames` to identity fields when canonical 5m/15m frames are already in `coreMarketPacket`.
2. Project optional context semantically instead of blind prefix slicing:
   - Cortex keeps priority professional trading sections.
   - Dynamic research keeps a few verified, relevant summaries/key points/source URLs.
   - Measured memory keeps lifetime totals, trade lessons, winners and counterexample losers, lane-aware analogs, and pre-entry-flow learning.
3. If still above the phase target, remove duplicate chart narrative detail while retaining full 5m/15m deterministic narrative; other timeframe truth remains in structured frames.
4. Only if still required, compact redundant market representations: pattern geometry, raw pivot/trend-line arrays, duplicate FVG/SMC prose, duplicated raw Fib/OTE inside SMC, excess pattern copies, and verbose HTF/timing frame fields.
5. Never silently drop the protected decision core. If the irreducible core itself cannot fit under the hard ceiling, return `JEV_CORE_CONTEXT_TOO_LARGE` and do not call the provider.

## Protected decision core

A SHA-256 digest is calculated before and after compaction over decision-critical truth. `coreTruthProtected=true` requires equality. The protected set includes:

- symbol, live price, contract and nearest level map
- complete 5m and 15m decision truth, including canonical FVG/OB/Fib/OTE data
- 1m and 3m timing truth including pre-move state
- compact 30m/45m/1h/4h/1d structure/location state
- R2544.21 pre-entry microstructure, including `samplingConfidence`, trap/support indices and flow persistence
- derivatives, observed liquidations, data quality and global context

Pattern drawing coordinates and long explanatory prose are not treated as independent market truth when an equivalent canonical numeric representation already exists.

## PASS-1 → PASS-2 handoff

PASS-2 no longer needs to infer/replay the whole PASS-1 request. PASS-1 returns an audited compact handoff containing:

- lane focus
- direction focus
- requested evidence families
- knowledge-research decision/family
- protected-core snapshot hash

PASS-2 receives this handoff together with the current core packet, executable plans, and only the material evidence collected for the final decision.

## Decision semantics preserved

R2544.22 does not change strategic authority or risk settings:

- JEV remains the final strategic decision maker.
- Radar remains attention-only.
- Workers remain evidence-only.
- No fixed score, 2-of-3 rule, or hard 15m strategic veto is introduced.
- R2544.21 sparse-flow confidence remains pre-entry timing evidence, not a probability or hard gate.
- Measured experience remains soft context; no self-modification or automatic rule promotion is added.
- Existing mandatory execution-integrity and exchange-safety controls remain unchanged.

## Office telemetry

Office now exposes the actual whole-request hard ceiling, phase target, target-exceeded flag and `coreTruthProtected` state. The rolling 60-minute health also reports PASS-1 and PASS-2 call counts, hard blocks and target exceedances separately.

This makes a future regression visible as a context-budget problem rather than a false “no signal” diagnosis.

## Regression coverage

R2544.22 adds tests for:

- oversized PASS-1 request projected to the 42 kB target while protected core remains byte-semantic equivalent
- oversized PASS-2 request projected to the 46 kB target while plans, requested evidence and PASS-1 handoff remain present
- irreducibly oversized protected core failing closed with `JEV_CORE_CONTEXT_TOO_LARGE`
- functional PASS-1 → PASS-2 audited handoff
- runtime/Office hard-budget telemetry

Full suite: **559/559 PASS**.
